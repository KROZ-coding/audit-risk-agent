AI 审计系统 · 跃迁指南

SYSTEM DEPLOYMENT PROTOCOL

无需理解底层逻辑，跟随光标，完成系统部署。
本指南已集成防错协议，请严格遵照指令执行。

🛠️ 阶段一：核心组件注入

在唤醒系统前，需向宿主环境注入以下三个基础依赖：

  1. 安装 Python 神经网络 (≥ 3.12)： 前往 Python 官网 下载并安装。
    ⚠️ 致命警告：安装界面最下方，必须勾选 Add Python to PATH！
    若遗漏此协议，后续所有指令将因找不到路径而全面崩溃。
  2. 装载 C++ 运算引擎： 点击 获取 Visual C++ 运行库，双击执行，一路“下一步”。
    （缺失此组件将导致数据可视化模块瞬间解体）
  3. 获取 AI 核心密钥 (API Key)： 登录 DeepSeek 控制台，在左侧菜单生成并复制一串以 sk- 开头的最高权限密钥，存入本地剪贴板。

🟢 阶段二：终端唤醒与协议解除

STEP 01 建立直连通道

打开项目根目录（包含 start.ps1 的文件夹），在顶部地址栏中清空原有路径，输入 powershell 并敲击 Enter。

💡 空间折叠技术：此操作将直接在当前维度（文件夹）撕开一个命令行终端，免除繁琐的路径寻址。

STEP 02 解除安全封印

复制以下指令至终端，解除 Windows 脚本执行限制（若弹出红字警告，输入 Y 确认）：

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

STEP 03 部署 uv 跃迁引擎

注入国内清华镜像节点，极速下载包管理引擎：

pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple
🛑 时空断层警告：
上述指令执行完毕后，必须强制关闭当前终端窗口！
随后重复 STEP 01 重新唤醒终端。此举旨在刷新系统环境变量，否则引擎将无法被识别。

🟡 阶段三：引擎点火与密钥绑定

（确认你已处于重新唤醒的全新终端中）

STEP 04 修复乱码 & 注入密钥

执行以下复合指令。系统将自动修复 Windows 5.1 终端的中文解码缺陷，并弹出配置面板：

# 修复 PowerShell 中文乱码缺陷 (强制 UTF-8 BOM)
$f = '.\start.ps1'; $c = [System.IO.File]::ReadAllText((Resolve-Path $f).Path, [System.Text.Encoding]::UTF8); [System.IO.File]::WriteAllText((Resolve-Path $f).Path, $c, [System.Text.UTF8Encoding]::new($true))

# 生成环境配置并唤起编辑器
copy .env.example .env
notepad .env
📝 密钥绑定协议：
1. 在弹出的记事本中，定位至 OPENAI_API_KEY=... 节点。
2. 将等号右侧替换为你在【阶段一】获取的真实 API Key。
3. 确保整个文件中仅保留一个有效的 API Key（删除其他带 # 的冗余假密钥）。
4. 按 Ctrl + S 保存并关闭面板。

STEP 05 点火升空

执行最终指令。系统将自动构建沙盒环境、下载百兆级依赖矩阵，并唤醒 Web 控制台（耗时约 1~3 分钟）：

# 构建环境并同步所有依赖矩阵
uv sync

# 唤醒主程序 (浏览器将自动弹出)
.\start.ps1
🎉 跃迁成功：若浏览器自动加载出深色科技风控制台，说明系统已完全接管。开始享受 AI 审计带来的降维打击吧！

☕ 阶段四：日常巡航模式

首次部署完成后，后续每次唤醒系统仅需 3 秒：

极速巡航指令：
在项目目录唤起终端后，直接输入以下指令（跳过环境同步）： 
.\start.ps1 -SkipSync

📚 阶段五：知识库投喂协议

将 UTF-8 编码的 .txt 格式法规或案例文件，直接投入项目内的 knowledge_base/ 维度中。
随后在 Web 控制台左侧点击 🔄 重载知识库，AI 将瞬间完成新知识的神经元突触连接。

🆘 异常捕获与修复手册

❓ 异常代码：uv 不是内部或外部命令
诊断：时空断层。你在安装引擎后未重启终端。
修复：关闭终端，重新执行【STEP 01】，随后从【STEP 04】继续。
❓ 异常现象：Network Error 或 AI 逻辑链断裂
诊断：密钥失效、余额耗尽或存在多重密钥冲突。
修复：终端输入 notepad .env 重新校验密钥，保存后按 Ctrl + C 终止进程，重新点火。
❓ 异常代码：DLL load failed 或可视化模块崩溃
诊断：缺失 C++ 底层运算库。
修复：返回【阶段一】安装 Visual C++ 运行库，随后重启宿主机器。
❓ 异常代码：端口 5000 被占用
诊断：当前维度的 5000 端口已被其他进程占据。
修复：将点火指令替换为 .\start.ps1 -Port 8080，随后手动访问 http://localhost:8080。
