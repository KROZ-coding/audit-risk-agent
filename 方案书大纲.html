P2问题定义与业务背景

专业深度 25
  • 痛点：四大所年报审计人工翻阅耗时、风险点分散、强经验依赖；中小所更缺高级审计人力
  • 为什么用 Agent 而非普通脚本：需要自主决策工具链调用顺序 + 可解释的推理链，而非固定流程
  • 目标用户：CPA 事务所审计助理 / 内审人员 / 监管初筛
  • 价值主张：把「翻报表找异常」压缩成「上传即出结构化风险台账」
技术主体

P3系统总览 + 架构图 ★核心页

技术创新 25
  • 必画一张主架构图：用户上传 → 预处理并行层（校验/指标/披露）→ ReAct Agent（13 工具）→ 分级门禁 → 三方辩论仲裁 → 综合评分 → PDF/Excel/图表导出
  • 技术栈标注：FastAPI + LangGraph ReAct + DeepSeek-V4 + ChromaDB（回退 TF-IDF）
  • 强调「固定工具链 + 自主决策」的混合架构：既灵活又可控
这一页是评委形成第一印象的地方，架构图要清晰、有数据流箭头，别堆文字。

P4五大风险维度模型

专业深度 25
  • 财务风险 / 关联交易 / 信披合规 / 持续经营 / 监管处罚 —— 五维覆盖
  • 量化判定阈值表：OCF/NP<0.5 连续 2 期、商誉/净资产>30% 未减值、存贷双高、大股东质押>70% 等
  • 十行业基准阈值表（毛利率/资产负债率/应收占比/存货周转/流动比率）
  • 强调审计措辞规范：用「风险嫌疑/异常迹象」而非定性结论，对齐 CAS 审计准则
